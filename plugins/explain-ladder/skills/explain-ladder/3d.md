# Level 3 variant — 3D scene

Read this file when `SKILL.md` sends a level 3 page to the 3D variant.
Every level 3 rule in `SKILL.md` still applies. This file adds the rules for the scene.
Paths in this file are relative to this skill's directory.

Reference implementation: `examples/postgres-write-path-3d.html`.
It follows one Postgres `UPDATE` through shared buffers, WAL, a crash, recovery, and a checkpoint in 10 steps.
Copy its structure. Do not copy its content.

## 1. Plan the scene before you write code
1. List the parts. Use the same names as levels 1 and 2. Keep 3 to 9 parts.
2. Give each part a place in space that carries meaning.
   Example: memory is the top layer, and disk is the bottom layer.
3. Write one row per step: the parts in focus, the camera, the arrows shown, and the world state at the end of the step.
4. Pick one concrete example with real names and values.
   Mark invented values (IDs, offsets, file paths) as examples on the page.

## 2. Page layout
- Put the 3D stage on the left and a step panel on the right. Below 860 px width, stack the panel under the stage.
- The panel holds these items, top to bottom:
  1. The step counter ("3 / 10") and one clickable dot per step.
  2. The step title and one or two sentences. Add a code block or a short note only when the step needs it.
  3. A "현재 상태" readout: one row per part, with the part's state in words.
     Highlight the rows that changed in this step. The readout is the text equivalent of the scene.
  4. A color legend.
  5. The "이전", "다시 재생", and "다음" buttons.
- Put a "시점 맞추기" button on the stage. It flies the camera back to the view of the current step.
- Show the mouse and touch controls in one line at the bottom of the stage.

## 3. Libraries
- Load three.js as ES modules through an import map. Pin the exact version.
  Give every module URL that the page loads an `integrity` hash, so the browser refuses a changed file:
  ```html
  <script type="importmap">
  { "imports": {
    "three": "https://cdn.jsdelivr.net/npm/three@0.160.0/build/three.module.js",
    "three/addons/": "https://cdn.jsdelivr.net/npm/three@0.160.0/examples/jsm/"
  }, "integrity": {
    "https://cdn.jsdelivr.net/npm/three@0.160.0/build/three.module.js": "sha384-61S/Nu32S3E5+n+KpCOTb2eRYps6fVKm+9Gz1QBvSePFthb46f063Aa/qe/lykFZ",
    "https://cdn.jsdelivr.net/npm/three@0.160.0/examples/jsm/controls/OrbitControls.js": "sha384-qlO/ZugKPxAQUAvTlQoo0QECzxJIJySZmCF/DHdb2Xn/hHndFwX/vfUAC9Hbk6LP",
    "https://cdn.jsdelivr.net/npm/three@0.160.0/examples/jsm/renderers/CSS2DRenderer.js": "sha384-oxPlnJSeUCYU9W3RMQswb4S/vFd4Bhxuy1Ffx0V2KJakWeb6n1gaqUtSE9Ic/F72"
  } }
  </script>
  ```
- The three hashes above are for three 0.160.0. If you import another addon, add its full URL and hash.
  A URL without an `integrity` entry loads unchecked. Compute a hash with:
  ```bash
  echo "sha384-$(curl -fsSL "$URL" | openssl dgst -sha384 -binary | openssl base64 -A)"
  ```
- Since three 0.148.0, the addons (`OrbitControls`, `CSS2DRenderer`) ship only as ES modules.
  A `<script src>` global build cannot load them.
- Use `OrbitControls` for rotate, zoom, and pan. Use `CSS2DRenderer` for labels.
- Do not add post-processing (`EffectComposer`, bloom). It adds build time and explains nothing.

## 4. Scene rules
- Build parts from boxes and cylinders. Add `EdgesGeometry` outlines so that the shapes read like a diagram.
- Draw each arrow as a `TubeGeometry` along a `QuadraticBezierCurve3`, with a cone at the end.
  Number the arrows. Use the same numbers in the summary step's list.
- Write labels as DOM elements through `CSS2DObject`. DOM text stays sharp at any zoom, Hangul included.
  - `center.set(0.5, 1)` puts the label above its anchor point.
  - `center.set(0.5, 0)` puts the label below its anchor point.
- Give each part one name label. Under the name, show a short state line only while the step focuses that part.
- Fade the parts that the step does not focus: material opacity 0.16, label opacity 0.25.
- Read colors from the page's CSS color tokens with `getComputedStyle`, and convert them to `THREE.Color`.
  Repaint every material when `prefers-color-scheme` changes or when the `data-theme` attribute changes.
- Create the renderer with `alpha: true`. Paint the stage background with CSS tokens.
- Cap the pixel ratio at 2. Size the renderer and the label layer with a `ResizeObserver` on the stage.

## 5. Steps, camera, and animation
- Define each step's camera as a target point plus azimuth, elevation, and distance.
  If the stage is narrower than the aspect that you designed the views for, increase the distance.
- When a step opens, fly the camera to its view in about 1 second. If `prefers-reduced-motion` is set, jump.
- Animate each step from the end state of the previous step to its own end state, then apply the end state.
  Then "이전", the step dots, and "다시 재생" all use one function.
- Cancel old animations with a generation counter.
  An old animation must not hide an object that the new step shows.
- A drag on the stage cancels the camera flight. The user can rotate at any time.
- Open step N at its end state when the URL ends in `#sN`, for example `#s3`. The screenshot checks use this.

## 6. Failure handling
- Put the step data and the panel code in a classic `<script>`. Put the scene in a `<script type="module">`.
  If the CDN or WebGL fails, the panel still works.
- If the scene is not ready after 8 seconds, show a message in the stage.
  Show the same message if `WebGLRenderer` throws.

## 7. Check once, then publish
With the Claude Code `Artifact` tool, write the page without doctype, `<head>`, and `<body>`. The tool adds them.
For a local check, wrap a copy of the page in a full HTML document.

1. Take screenshots of 4 to 6 steps with headless Chrome or Chromium. On macOS:
   ```bash
   "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new \
     --use-angle=swiftshader --enable-unsafe-swiftshader --hide-scrollbars \
     --virtual-time-budget=9000 --window-size=1280,800 \
     --screenshot="$PWD/s3.png" "file://$PWD/test.html#s3"
   ```
   Check that every focused part is in the frame. Check that no label covers another label.
2. Check the phone layout inside a 400 px wide `<iframe>`.
   On macOS, headless Chrome lays out at 500 px or wider, even with `--window-size=400,...`.
3. Check the light theme with `--blink-settings=preferredColorScheme=1`.
   On macOS, headless Chrome follows the system theme without this flag.
4. Run every animation once. Append a script to the test copy that clicks "다음" every 4.5 seconds.
   Have it log `error` and `unhandledrejection` events. Run with `--enable-logging=stderr`
   and `--virtual-time-budget=52000`, then search stderr for the logged errors.
5. Fix what the checks show in one pass. Then publish.
6. Tell the user what you could not check, for example the module load inside the page viewer.

## Cost
The reference page has about 980 lines. A 3D page takes more build time than a 2D page.
If the topic has no depth, a 2D page explains it better for less.
